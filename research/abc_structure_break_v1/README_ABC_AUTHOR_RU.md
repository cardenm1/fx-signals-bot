## Правила и исследовательские допущения

Последовательность из материалов пользователя: **импульс H1/H4 → возврат в блок начала импульса → слом на младшем ТФ по четырём точкам → откат → закрытое свечное поглощение → вход**. Основные пары H1/M5 и H4/M15 проверяются отдельно. BUY — зеркальное допущение к показанному SELL. Результаты не подтверждают прибыльность.

Числовые правила, которых нет в авторских материалах, — явные исследовательские допущения:

1. Структура по BID. Pip=0,0001, шаг=0,00001. Метки CSV — начало свечи UTC. H1 состоит из 12 последовательных закрытых M5, H4 из 48, M15 из 3. H4 привязан к 00/04/08/12/16/20 UTC. Неполные интервалы исключаются; разрыв M5 сбрасывает контексты.
2. Pivot — строгий high/low среди двух свечей слева и двух справа; доступен только после закрытия второй правой свечи. Равенства и одновременный high/low одной свечи исключены.
3. SELL-импульс: подтверждённый структурный low, затем подтверждённый high начала движения, затем закрытие H1/H4 ниже low минимум на шаг. Одной тени недостаточно. BUY зеркально. Ложные пробои без такого импульсного контекста этой ревизией не проверяются.
4. Блок — полный high–low последней противоположной свечи на origin-pivot или до него, максимум за шесть старших свечей, в непрерывном сегменте. SELL использует бычью свечу, BUY медвежью. Если свечи нет или импульс не вышел из блока — контекста нет. Срок действия 72 календарных часа; выход за дальнюю границу более чем на 1 pip отменяет контекст.
5. Возврат — пересечение диапазона более поздней закрытой M5 с блоком. На той же свече контекст и возврат не создаются. Младшие точки должны начаться после доступности касания блока; прошлые точки не подставляются задним числом.
6. SELL: p1 high → p2 low → p3 high ниже p1 → p4 low ниже p2, минимум на шаг. p1 внутри блока. Нужен закрытый младший пробой p2 после доступности p3, не позднее подтверждения p4. BUY зеркально. Формация фиксируется после подтверждения p4.
7. Затем нужна более поздняя противоположная свеча коррекции и свеча поглощения. Тело текущей свечи полностью покрывает предыдущее противоположное тело, хотя бы одна граница строго шире. Тени не участвуют. Поглощение до слома входа не даёт. Если цена уже прошла p4 по направлению сделки, вход не догоняется.
8. SL за более дальним из p3 и экстремума отката от p4 до входной свечи, буфер 1 pip. Один контекст даёт максимум один вход; независимые сделки могут перекрываться.
9. Два выхода исследуются отдельно: 2R и обновление точки 5 старшего ТФ. Точка 5 — причинная аппроксимация: крайний экстремум импульса до первой M5 возврата в блок, без диапазона самой свечи касания; замораживается при касании, TP на шаг за ним. Будущая точка не используется. Если цель к входу уже позади цены — сделка этого варианта пропускается.

## Локальное воспроизведение

Для синтетических тестов исторические данные и секреты не нужны:

```bash
cd research/abc_structure_break_v1
python -m pip install -r requirements-abc-author.txt
python -m unittest discover -s tests_author -v
python -m abc_author.notify test-message
```

Последняя команда — dry run без сети. Все 20 тестов проверены в каталоге без истории. Telegram-транспорт в тестах подменён; настоящее сообщение не отправлялось.

Для исторического теста укажите собственные локальные CSV. Требуются timestamp с явным часовым поясом и open/high/low/close; BID и ASK синхронны, строго упорядочены, без дубликатов. Программа не загружает историю из сети:

```bash
python -m abc_author.research --bid /local/private/BID.csv --ask /local/private/ASK.csv --out abc_author_results --audit
```

Результаты, включая подробные журналы, создаются только локально. `.gitignore` исключает историю, журналы, архивы, .env и состояние. Если нужен `abc_author.validate`, положите приватные CSV под его стандартными локальными именами `abc_author_data/GBPUSD_BID_M5_CLEAN.csv` и `GBPUSD_ASK_M5_CLEAN.csv`, выполните research с каталогом `abc_author_results`, затем `python -m abc_author.validate`. Эти каталоги не публикуются.

Вход на следующем последовательном M5 open после закрытого поглощения: BUY по ASK+0,2 pip, SELL по BID−0,2 pip. BUY выходит по BID, SELL по ASK; исторический spread включён. На SL/time exit ещё 0,2 pip adverse slippage, TP без slippage. При SL и TP внутри одной M5 первым считается SL. Gap за SL — по неблагоприятному open, за TP — по TP без улучшения. Time exit через 288 непрерывных M5. Неизвестные исходы при разрыве/конце данных показаны отдельно. Комиссия и swap в базе 0; дополнительная задержка не моделируется.

## Telegram и workflow

Отдельные `notify.py` и `telegram.py` реализованы. Имена переменных — `ABC_AUTHOR_TELEGRAM_BOT_TOKEN` и `ABC_AUTHOR_TELEGRAM_CHAT_ID`; значений в репозитории нет. Реальная доставка не проверена, публикация этого PR ничего не отправляет. Для источника свежих данных нужны отдельные локальные BID/ASK CSV. Незакрытые свечи отбрасываются, источник и сигнал старше 15 минут отклоняются.

SQLite резервирует уникальный ID с commit до отправки. После перезапуска повторная попытка не отправляет дубликат; uncertain не повторяется автоматически. Возможна потеря уведомления при сбое, exactly-once не обещается. Инициализация подавляет старые сигналы. Поддержка GitHub checkpoint в CLI требует отдельного явного ручного включения и не используется новым workflow.

Новый `.github/workflows/abc-structure-break-author.yml` имеет только `workflow_dispatch`, права contents read, синтетические тесты и dry run. Нет schedule/push/pull_request triggers, Secrets, реальных отправок или загрузки артефактов. Исторический тест остаётся локальным, поскольку данные не публикуются.

Итоговые показатели и ограничения: [REPORT_RU.md](REPORT_RU.md). `MANIFEST_SHA256.json` перечисляет только новые публичные файлы и их SHA256 относительно корня репозитория.
