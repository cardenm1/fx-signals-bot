# GBP/USD: строгая D1 → H1 → M5 в paper-режиме

**Статус: подготовлено, наблюдение не запущено.** Операционные команды ниже выполняются только после разрешения пользователя. Автоматическая публикация отсутствует; расписание, GitHub Actions и работающий Telegram-бот не используются.

## Что сохранено

В `frozen/recognize.py` находится побайтовая копия исходного строгого распознавания с SHA256 `fa8c5d24d972316d885760f63ce91666f71f2fe10f3b8cc94d26679e4ca040b9`.

D1: UTC 00:00, структурное направление по двум подтверждённым high/low, swing 2/2, фиксированная зона ±0,20 ATR14, две реакции с учётом seed, последующие касания/отбои с интервалом ≥3 торговых D1, включая прежнее правило глубоких ложных пробоев; возраст до 60 D1 и прежнее аннулирование. H1: закрытие за внешней границей с буфером 0,05 лагированного ATR14. M5: подтверждённая локальная ликвидность, снятие с буфером 0,10 ATR, возврат в той же свече, затем отдельный BOS с буфером 0,05 ATR по уровню, замороженному при снятии. Окно шесть часов; pivot известен до открытия проверяемой M5. Динамический BOS, новый фильтр глубоких пробоев и альтернативные параметры не подключены.

Модель проверяет свой хеш. Каждая сессия дополнительно фиксирует хеши кода наблюдателя, параметры исполнения и версии pandas/numpy. При изменении кода или исходного warmup продолжение старой сессии запрещается. Две диагностические функции повторяют условия только для объяснения статусов и сверяются с исходным распознаванием; сигналы берутся непосредственно из frozen-модуля.

## Новые данные и старт

История 2025–2026 уже использовалась; она допускается только как предыстория для расчёта D1/ATR. При разрешённом `init` начало наблюдения устанавливается автоматически: максимум из ближайшей следующей M5-границы текущего UTC-времени и `2026-10-24T00:00:00Z`. Аргумента для старта задним числом нет. Для журнала сигналов BOS-свеча должна открыться не раньше этой границы. Старые сигналы не попадают в forward-журнал, виртуальные сделки по ним не реконструируются.

Перед стартом нужно дополнить предысторию до актуальной закрытой M5 командой `bootstrap`. Начальная история не должна отставать более чем на один ожидаемый активный час. Выходные определяются прежней NY17 Forex-неделей, поэтому обычные выходные сами по себе не означают устаревший warmup. Праздники/пропуски не заполняются; невалидные D1 обрабатываются прежними правилами.

Сборщик использует `dukascopy-python==4.0.1`, запросы **TICK**, содержащие обе стороны, и собирает из них M5 `[t,t+5min)` UTC. Для актуальных данных обычный исторический M5-fetch может запаздывать; он используется только при подготовке предыстории. [Документация автора библиотеки](https://pypi.org/project/dukascopy-python/) описывает различие исторического OHLC и получения данных на основе тиков. Это read-only сторонний клиент к Dukascopy, без брокерского аккаунта.

Живой адаптер в рамках подготовки **не запускался и не проверялся в сети**. До разрешённого пилотного `once` нельзя утверждать, что текущий внешний API отдаёт достаточно свежие котировки. Сетевой запрос ограничен 30 секундами, при зависании дочерний процесс останавливается; ошибки записываются, свечи и цены не придумываются.

Прежняя независимая сверка подтвердила open-label на 24 выбранных исторических свечах, включая окрестности всех пяти сигналов, но не весь CLEAN-файл. Этот предел проверки warmup сохраняется. Новые M5 формируются из UTC-времён самих новых тиков.

## Исполнение виртуальной сделки

1. Подтверждённый сигнал фиксируется при закрытии BOS M5. В `signals.csv` цена `entry` — **индикативный ASK close BUY / BID close SELL**, помеченный `INDICATIVE_SIGNAL_CLOSE_NOT_FILL`; SL — BID low свечи снятия для BUY / ASK high для SELL. Показанный TP предварительный.
2. Реальный для paper-модели `ENTRY` записывается отдельным новым событием в `trades.csv` **через полную M5 (300 секунд)** после сигнала. Используется последняя свежая котировка, реально полученная на текущем опросе, а не реконструированное задним числом открытие бара. BUY — ASK, SELL — BID. Записываются источник UTC, время наблюдения, возраст quote, опоздание, спред и дополнительное проскальзывание.
3. Допустимый возраст quote 30 секунд; опоздание входа максимум 60 секунд. Эти ограничения относятся к качеству исполнения, не меняют правила распознавания. Поздно обнаруженный сигнал остаётся в журнале, но получает отказ во входе. При входе уже за структурным SL — отказ. Одновременно одна позиция; отказанные сигналы не ставятся повторно в очередь.
4. TP пересчитывается **2R от фактической paper-цены входа и неизменного SL**. Это отдельное событие, строка первоначального сигнала не редактируется. Связь журналов — `signal_id`.
5. Открытая позиция проверяется по новым тикам: BUY закрывается по BID, SELL — по ASK. SL исполняется по первой доступной противоположной котировке с неблагоприятным проскальзыванием; TP моделируется лимитом по целевому уровню. На гэпе результат может быть хуже −1R. Нельзя считать исполнение гарантированным реальным брокерским fill.
6. Дополнительное проскальзывание задаётся один раз при `init`, по умолчанию 0 pip, как в контрольном тесте. Изменить его в старой сессии через CLI нельзя. Входной и стоповый adverse slip записываются явно; фактический спред берётся из котировки. Комиссия, swap и отдельные расходы конвертации не моделируются. Переоценка виртуальных позиций ведётся в R без настоящих денег.
7. На `EXIT`: `R = side × (exit−entry) / initial_risk_price`. Это реализованный результат **виртуальной модели**, не отчёт о реальной биржевой сделке. При потере данных или quote-gap >5 минут сохраняется флаг неопределённости. Последующее восстановление тиков допускает добавление поздно обнаруженного выхода с двумя временами — source/event и observed; прежние записи не меняются. Открытые позиции без котировок не получают выдуманный окончательный результат.

## Журналы и восстановление

| Файл в каталоге сессии | Назначение |
|---|---|
| `events.csv` | Первичный журнал всех событий, последовательность и SHA256-цепочка |
| `signals.csv` | По одной строке на подтверждённый новый сигнал, индикативная цена, SL/TP, UTC, направление, зона, спред |
| `trades.csv` | Новые строки ENTRY, EXIT и TRADE_GAP; фактические paper-цены и реализованный R |
| `rejections.csv` | Отказы исполнения, истечение M5-окон и часовая диагностика фильтров |
| `errors.csv` | Ошибки сети/данных и HALT |
| `stages.csv` | Создание/важность/аннулирование D1-зон, H1-контексты, M5 sweep-return, ожидание BOS, heartbeat, пропуски |
| `warmup_BID.csv`, `warmup_ASK.csv` | Неизменяемые снимки предыстории с проверяемыми хешами |
| `raw/*.csv` | Сохранённые пакеты новых тиков с SHA256 и ссылками SOURCE_BATCH |

Файлы производных журналов появляются при первом соответствующем событии; отсутствие `signals.csv` до первого сигнала нормально. В `payload_json` сохраняются полные поля, основные поля также вынесены в плоские CSV-столбцы. UTC `event_utc` и `observed_utc` различаются намеренно.

Записи открываются только с `O_APPEND`, фиксируются `fsync`; одновременно разрешён один writer через `flock` (macOS/Linux, на Windows использовать WSL). Идентификаторы событий детерминированы: повторный опрос не создаёт повторного сигнала. После перезапуска состояние и позиция восстанавливаются из событий. Если программа успела записать первичное событие и упала до CSV-проекции, недостающая строка проекции дописывается.

Редактирование существующих строк, изменение warmup/raw или обрыв CSV-строки приводят к отказу в продолжении. Автоматической обрезки или «починки» журнала нет. Изменение закрытой свечи поставщиком записывается как ошибка и HALT; допускается лишь вычислительная разница float ≤1e−12 цены, гораздо меньше price point. Позднее заполнение уже пройденного пропуска также вызывает HALT, поскольку изменило бы прошлое. При HALT существующая позиция остаётся нерешённой, её результат не выдумывается.

Хеш-цепочка помогает обнаруживать изменения, но не является внешней нотариальной защитой от владельца, переписавшего весь каталог и пересчитавшего хеши. Для независимого forward-протокола сохранять ежедневные копии/хеши отдельно. Для анализа копировать CSV, а не сохранять изменения редактором в оригиналы.

## Запуск только после разрешения

Операционные команды `bootstrap/init/once/run` ниже даны как инструкция и при подготовке **не выполнялись**. Офлайн-тесты выполнены отдельно, без запуска источника.

Из корня локального `fx-signals-bot`, Python 3.12:

```sh
python3 -m venv research/paper_watch/.venv
source research/paper_watch/.venv/bin/activate
python -m pip install -r research/paper_watch/requirements.txt
python -m unittest research.paper_watch.test_watch -v
```

После отдельного разрешения сначала подготовить свежую предысторию в новом каталоге:

```sh
python -m research.paper_watch.cli bootstrap --approve-paper \
  --bid research/data/GBPUSD_BID_M5_CLEAN.csv \
  --ask research/data/GBPUSD_ASK_M5_CLEAN.csv \
  --out research/paper_watch/bootstrap/session_001
```

Затем создать новую сессию — UTC старта фиксируется в этот момент:

```sh
python -m research.paper_watch.cli init --approve-paper \
  --bid research/paper_watch/bootstrap/session_001/GBPUSD_BID_M5.csv \
  --ask research/paper_watch/bootstrap/session_001/GBPUSD_ASK_M5.csv \
  --session research/paper_watch/runs/session_001 --slippage-pips 0
```

Пилотный опрос и проверка:

```sh
python -m research.paper_watch.cli once --approve-paper \
  --session research/paper_watch/runs/session_001
python -m research.paper_watch.cli verify --session research/paper_watch/runs/session_001
python -m research.paper_watch.cli status --session research/paper_watch/runs/session_001
```

Сначала проверить `errors.csv`, свежесть TICK_CURSOR в `events.csv`, SOURCE_BATCH и `raw/`, отсутствие HALT, новую UTC-границу старта, DATA_GAP и heartbeat. Если котировки запаздывают, система должна отвергать вход, а не создавать красивые задние исполнения.

Только после успешного пилота и разрешения на длительное наблюдение:

```sh
python -m research.paper_watch.cli run --approve-paper \
  --session research/paper_watch/runs/session_001 --poll-seconds 15
```

Это обычный foreground-процесс; компьютер и терминал должны оставаться работающими. `Ctrl+C` завершает процесс, состояние уже сохранено; виртуальная позиция автоматически не закрывается. Повторный `run` восстанавливает ту же сессию. Для `status/verify` остановить writer, поскольку второй процесс сессии блокируется. Команды записи без `--approve-paper` завершаются до подключения к источнику и создания сессии. Флаг — защита от случайного запуска, а не замена согласия пользователя.

Ни Telegram/почтового отправителя, ни брокерского маршрутизатора в модуле нет. Планировщики/Actions не создавались. Любая будущая публикация — отдельное изменение и отдельное разрешение.

## Исправления технической надёжности

Успешная обработка имеет отдельное событие `ANALYSIS_CHECKPOINT` с UTC-временем открытия последней обработанной свечи. Сохранённые BAR после этой отметки анализируются повторно, в том числе до следующего сетевого запроса. Повторная обработка использует стабильные идентификаторы событий; журналы не переписываются. `status` показывает `last_processed_bar`.

При сбое сначала читается первичный журнал, затем достраиваются недостающие CSV-представления. Повреждённый/недописанный хвост по-прежнему останавливает работу для ручного расследования: автоматического удаления строк нет.

Загрузчик тиков требует явные `request_start` и `request_end`. Первая допустимая свеча начинается не раньше округлённого вверх начала запроса; её конец должен находиться внутри покрытия запроса и отстоять от времени получения минимум на две секунды. Начатая внутри интервала загрузка исключает весь первый неполный M5. Запросы планируются по границам M5. Полное временное покрытие успешного запроса не доказывает отсутствие потерянных тиков у поставщика.

Пустой ответ в ожидаемые выходные записывается как `MARKET_CLOSED` в `market.csv`, если нет отсутствующих активных интервалов после последнего сохранённого бара. Календарь использует пятницу/воскресенье 17:00 `America/New_York`, включая DST; D1 остаётся UTC 00:00. Ошибки соединения и пустые ответы за активные интервалы остаются в `errors.csv`. Праздничные закрытия не предполагаются автоматически.

Изменение runtime-хешей намеренно запрещает запуск старой сессии новым кодом. Старые журналы сохраняются; перед разрешённым запуском создайте новую папку сессии штатной командой `init`, используя актуальную закрытую историю для прогрева. Не редактируйте INIT и хеши старых журналов. Исправления сами по себе не дают разрешения запускать `once`/`run`.

Офлайн-проверка из корня репозитория:

```sh
python -m unittest research.paper_watch.test_watch research.paper_watch.test_fixes -v
```

Новые тесты используют временные синтетические журналы и инъекции сбоев. Сеть и работающий наблюдатель им не нужны.
